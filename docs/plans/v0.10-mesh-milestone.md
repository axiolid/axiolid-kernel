## #84 design decision (measured, not assumed)

PROBE RESULT (`boolmesh` difference, input with a normals channel):
`input normals present=true, output normals present=false` — attributes are
**silently dropped today**, with no error and no report.

Crucially this is DELIBERATE, not an oversight. `convert.rs::from_manifold`
documents it: boolmesh computes FACE normals, and re-exporting those as VERTEX
normals "would misrepresent hard edges created by the cut."

So #84 is NOT "make attributes survive every operation" — that would force a
lie at exactly the cut boundary. #84 is **make the fate of each channel
explicit and typed**, so a consumer learns what happened instead of comparing
`is_some()` before and after.

Design: carry attribute fate in the EXISTING `BooleanEvidence` channel
(`crates/contracts/operations/mesh-boolean/src/evidence.rs`), which already
follows this philosophy for `disjoint_tools`: "not an error here, so it is
reported rather than rejected." No new plumbing invented.

Policy vocabulary (per channel): Preserved / Interpolated / Dropped(reason).
An operation that creates new vertices must state which applies.
